Statements After the Terminator

codeintel-code-reachability-analyzer analyses code to identify potentially unreachable code blocks based on static analysis, and this can help identify dead code and potential logical errors. It works on the Python AST directly, checking each statement list for statements after a return, raise, break, or continue, and reports every following statement in that list, each with its own line.

Every Following Statement Reported

Every following statement in the list is reported, not only the first, each with its own line.

Exclusions by Normalised Path

An exclusion entry naming a directory excludes everything under it, and exclusion entries are compared as normalised absolute paths.

A File That Cannot Be Read Exits 1

A named file that cannot be read or parsed produces an error result and the run exits 1.

Parameters, Three Entries and No More

-hShows a help message and exits.
-vListed with no description provided. The absence is recorded as the README's own gap rather than filled.
-eGives the list of files or directories to exclude from analysis. The directory exclusion and normalised path rules in the first panel belong to this entry.

-v Has No Description in the README

The parameter list leaves -v undescribed, exactly as the README leaves it.

Verified Behaviour and Limits

The checking is done on the Python AST directly, list by list, so only statements sitting after a terminator in the same statement list are reported. A statement in a different list is a different sorting pile and is not claimed by this panel.
